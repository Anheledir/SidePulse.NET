# Startup and size baseline — 2026-10-26

Issue: [#25](https://github.com/Anheledir/SidePulse.NET/issues/25).
AOT/trimming follow-up: [#26](https://github.com/Anheledir/SidePulse.NET/issues/26).

## Method

Release, self-contained single-file linux-x64, .NET SDK 10.0.100/runtime 10.0.0,
Linux 6.18.55/glibc 2.41, Intel Xeon Platinum 8573C, three logical CPUs exposed.
Baseline source: `26f64b9f864348e51684bf68f49095f151a3ba27`. The optimized
working-tree build is identified by its executable SHA-256 in the raw report.
Nine paired launches per command/cache mode; report medians, with all samples
retained below. Each pair starts with a new isolated bundle extraction directory
and then reuses it. This is **not cold OS page-cache or cold-boot measurement**.
Measurements include process launch through command exit; Home ends at its first
complete input guide in a real Unix PTY at 100x30, before selecting explicit Quit.
The application config location is isolated and must remain absent. No device,
phone token, bridge request or credential vault is required.

## Local Linux results

| Build / measurement | Empty bundle cache | Reused bundle cache |
|---|---:|---:|
| Baseline `--version` | 136.71 ms | 133.70 ms |
| Optimized `--version` | 29.22 ms | 29.15 ms |
| Compressed baseline `--version` | 209.51 ms | 204.02 ms |
| Baseline state preview | 170.78 ms | 172.55 ms |
| Optimized state preview | 176.61 ms | 169.04 ms |
| Compressed baseline state preview | 244.81 ms | 266.28 ms |
| Baseline Home | 455.27 ms | 464.61 ms |
| Optimized Home | 193.38 ms | 187.99 ms |
| Compressed baseline Home | 527.29 ms | 527.40 ms |

Warm Home improves about 60%; the bare version probe improves about 78%.
State-preview differences are small enough to treat as shared-machine noise.

| Build | Executable bytes | Executable gzip bytes (level 6) | Observed extraction bytes |
|---|---:|---:|---:|
| Baseline | 76,610,475 | 33,159,265 | 0 |
| Optimized | 76,610,987 | 33,159,461 | 0 |
| Compressed baseline | 40,573,373 | 33,397,573 | 0 |

Gzip sizes refer to the executable only, not complete release archives/manifests.
The compressed experiment uses `EnableCompressionInSingleFile=true` against the
baseline. It cuts the managed bundle's on-disk executable size by about 47%, but
adds roughly 60–95 ms startup cost here and slightly increases gzip download size.
**Keep bundle compression disabled.** It works against the observed startup goal.
No trimming/AOT or framework-dependent requirement is introduced by this change.

## Cost attribution and changes

- Home formerly waited up to 300 ms for a missing host. It now probes for an
  immediately available connection, with a bounded response deadline. Normal host
  start/status/stop retain their existing wait/cancellation behavior. A busy or
  missing endpoint is labeled **not connected**, rather than declaring it stopped.
  PTY smoke verifies both missing-host navigation and an actual running dry-run host.
- Bare `--version`/`-v` now use a small bootstrap without terminal setup or the
  full command registry. Version calls with other flags retain normal parsing;
  quiet/noninteractive output equivalence is tested. The ~29 ms result is a
  runtime-plus-minimal-managed-work proxy, **not an isolated JIT profiler result**.
- In this Linux .NET 10 bundle, both an isolated extraction-directory inventory
  and host tracing observed no extracted native files for these commands. Empty
  versus reused extraction caches have no convincing startup premium here.
  Do not attribute these Linux timings to disk extraction or generalize them to
  Windows/macOS. The publisher still allows extraction when the runtime needs it.
- The CLI and Core assemblies are about 563 KB and 220 KB respectively in this
  build; Spectre.Console is about 848 KB, Spectre.Console.Cli 432 KB and QRCoder
  204 KB. The self-contained runtime/framework dominates the 76.6 MB executable.
  Embedded docs/licenses remain available. AOT/trimming compatibility and actual
  runtime/JIT/resource profiling remain the next investigation under #26.

## Reproduction and regression budget

```bash
dotnet publish src/SidePulse.Cli -c Release -r linux-x64 --self-contained true -p:NuGetLockFilePath=obj/packages.publish.lock.json -o /tmp/spn-publish
python3 scripts/benchmark_startup.py /tmp/spn-publish/spn --samples 9 --label candidate --output /tmp/startup.json
```

Publish a baseline into a separate directory with the same SDK, measure it first,
then pass `--compare /tmp/baseline.json` for the candidate. Keep individual samples
and executable hashes. Do not run benchmark pairs alongside heavy build/test work.
The initial shared-runner guard allows a median up to `baseline * 1.5 + 100 ms`
and executable growth up to 10%. This intentionally catches severe regressions,
not small scheduling noise; it is not a promise about every user's machine.

The **Startup benchmark** workflow builds baseline/candidate with one SDK on
native Windows/Linux/macOS, uploads raw reports and SDK information, and applies
that budget. Its manual baseline defaults to the pre-optimization commit above.
Windows command timings and cache inventories are automated; **Windows Home needs
an actual console/ConPTY measurement** and is not represented by redirected help.
Native architecture/OS numbers must remain distinct from cross-built packages.
