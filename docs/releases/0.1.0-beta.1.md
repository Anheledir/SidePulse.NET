# SidePulse.NET 0.1.0-beta.1

First beta candidate. The command is now **`spn`** (`spn.exe` on Windows).
The product and repository remain SidePulse.NET. No old-name alias is included.

## Changes

- Interactive launches stay open after commands. Home, section navigation and a
  searchable `/` action palette support repeated work; Esc at Home stays in the app.
- Send state keeps its output and Preview mode during the session. Choose a state
  and press Enter to send again. Output selection lists connected devices and saved phones.
- Script commands leave simple arguments unquoted and escape shell-sensitive values.
  Portable executable paths use an absolute invocation when `spn` is not on PATH.
- State, write, animation and host delivery select one mounted USB device, otherwise
  the saved default or sole phone. Explicit targets never fall back on failure.
- Native OpenCode event plugin joins Copilot, Codex, Claude Code and Kiro integrations.

## Downloads and installation

Choose exactly one archive for your OS and architecture:

| OS | x64 | ARM64 |
|---|---|---|
| Windows | `spn-win-x64.zip` | `spn-win-arm64.zip` |
| macOS | `spn-osx-x64.tar.gz` | `spn-osx-arm64.tar.gz` |
| Linux | `spn-linux-x64.tar.gz` | `spn-linux-arm64.tar.gz` |

Verify the archive against `SHA256SUMS`, then extract the **complete archive** into
its own permanent directory. Windows suggestion: `%LOCALAPPDATA%\Programs\SidePulse.NET`;
macOS/Linux: a user-owned directory under `~/.local/share/SidePulse.NET`.
Run `.\spn.exe` in PowerShell or `./spn` on Unix. An optional manual user PATH entry
lets other terminals use `spn`; reopen terminals after changing PATH.

This beta uses self-contained directory packages, not single-file executables.
Do not copy the apphost alone: runtime files and `sidepulse-install.json` are required.
There is no automatic installer, PATH/profile modification or signing in this beta.
`spn docs --offline` and `spn about licenses --full` work without a network connection.

## Upgrade from the alpha preview

1. With the **old executable**, stop the host and uninstall each managed integration
   using its existing `--config` override where applicable. Existing ownership checks
   refuse modified files; preserve those files and merge them manually.
2. Extract the new complete package into its permanent directory. Keep the old copy
   until the new setup is verified. Do not use the alpha updater to cross this rename.
3. Run `spn link list` and confirm saved phone aliases are present. Storage paths,
   native credential identity, profiles and IPC identity are unchanged.
4. Reinstall integrations with `spn agents install <provider>` from the permanent
   executable. Restart the agents and review their normal trust prompts.
5. Start the host, send one test state and verify the actual device display.
   Remove obsolete downloaded files manually after verification.

Existing provider filenames such as `sidepulse-net.json` and `sidepulse-net.js`
remain ownership identifiers. They are not compatibility executables.

## Validation and remaining limits

Native CI builds/tests on Windows x64, Linux x64 and macOS ARM64, exercises generated
hooks/plugins, and tests update replacement and rollback with simulated hardware.
Other architecture packages are cross-built; they still need native acceptance.

Real device/firmware parity and each installed agent version need separate recorded
acceptance. Bridge HTTP success does not acknowledge the physical LED display.
Linux saved links require Secret Service; macOS uses Keychain; Windows uses DPAPI.

The persistent UI is an initial delivery slice: comprehensive saved settings,
first-run installation, automatic managed-hook repair and the full responsive frame
remain open in issues #17/#18. Existing advanced setup forms are still guided menus.
Updates require stopping the host and running outside the installation directory;
retain backups until `spn update status` confirms success.

This release remains a **draft** until its packages and acceptance have been reviewed.
