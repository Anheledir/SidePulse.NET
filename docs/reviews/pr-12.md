# PR #12 architecture and QA review

Review dates: 2026-10-23 through 2026-10-24. Baseline: `444767f66cc6ca73f999339ba671923a10d61ffe`.
Scope: application architecture, credential and IPC boundaries, hook ownership,
terminal/script behavior, animation model, updater transactions, tests, workflows,
all eleven open issues, repository metadata and available security settings.
This is a maintainer-assisted review, not independent approval or a penetration test.

## Assessment

The Core/CLI split is appropriate: the transport, reducer, parser and update
transaction can be tested without Spectre or hardware. Native secret adapters
fail closed, hooks remain isolated from network delivery, shared config writes
preserve exact backups, and update replacement verifies both packages and files.
There is useful behavior coverage beyond happy paths, including crash recovery,
modified configuration, corrupt packages and actual startup-probe rollback.

PR #12 is an alpha implementation with substantial follow-up scope. Do not merge
it under a firmware-parity or production-ready claim. The review found no
confirmed critical vulnerability, but that is not evidence of absence. New
security checks and the review fixes must pass before merge. Hardware/provider
acceptance and the public update/release path remain explicit release gates.

## Architecture and test observations

- State aggregation is deterministic and provider-namespaced. Error retention and
  late-event handling have tests; receipt timestamps and bounded retention still
  need a documented operating policy (#5). A static dashboard is not a live one (#7).
- Native protection uses DPAPI or AES-GCM with native-vault keys. Link listing
  does not print tokens. Same-user IPC does not defend against compromised local
  user processes. No paid provider API or conversation transcript access is needed.
- LED envelope validation is intentionally separate from parser simulation and
  physical firmware acknowledgement. Upstream assets are attributed to a pinned
  revision. A golden conformance corpus is still missing (#2).
- Hook tests verify merging/ownership/backup behavior and generated wrappers.
  Provider versions, event payload drift and real trust prompts need manual checks.
- Shell command export has quoting tests; Unix PTY smoke covers menus/editor.
  Windows keyboard/clipboard and narrow-terminal usability remain manual checks.
  JSON conventions vary across commands/states; audit before promising a stable
  external schema (#7). Runtime errors belong on stderr.
- Updates reject unsupported runtimes, missing checksums, corruption, traversal,
  links and manifest mismatches. Installation replacement is two renames, not a
  crash-proof filesystem transaction. Backups/manual recovery remain necessary.
  Hashes from the same publisher are not independent signature verification.
- Release uses tested native CI and draft-first assets/checksums. Only the publish
  job has contents write. Wiki/upstream workflows execute from the default branch.
  No pull_request_target execution or permanent token was introduced.
